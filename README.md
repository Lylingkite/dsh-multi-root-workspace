# 多文件夹工作区

DeepSeek Harness 插件。在一个工作区关联多个项目目录，并用 `@` 搜索和引用其中的文件。支持 Windows 工作区和通过 `dsh-wsl-bridge` 打开的 WSL 会话。

## 安装

从 [GitHub Releases](https://github.com/Lylingkite/dsh-multi-root-workspace/releases) 复制所需版本的 `.tgz` 下载链接，在 DSH 的 **插件 → 添加插件** 中粘贴该链接。也可以运行 `dsh plugin --profile desktop add "<下载链接>"`，不需要把安装包保留在本地。

## 使用

1. 在工作区菜单中选择 **编辑工作区**，添加目录并保存。最多添加 24 个附加目录。
2. 输入 `@` 只显示已关联的根目录；选中目录按 **Tab** 查看当前层。直接输入 `@关键词` 可跨项目递归搜索。
3. 将附加目录设为主要目录并保存，会打开以它为根的原生工作区。新会话使用该根，旧会话留在原工作区。移除关联不会删除文件。

### 工作区项目关系（不用 @）

在「编辑工作区 → 项目关系」逐条保存跨项目职责和依赖，例如「网关调用订单服务查询订单状态」。关系绑定到当前工作区，不绑定某条聊天；同一工作区的新会话自动得到已保存的关系正文。新增或修改一条不会重写其他条目，新增目录也不清除已有关系。请先保存目录，再录入关系；不要填写密码或令牌。

### 在对话中加入项目说明

在聊天输入框输入 `@`，选中一个目录后发送即可。也可输入 `@目录/`；带空格的路径写成 `@"目录 名/"`。发送后优先读取根目录 README，并补充已有的 DSH 项目说明；没有文档才扫描结构，生成可直接用于本轮的底稿。只有当前会话允许写入时才新建项目说明，不覆盖已有文件，也不改工作区关联设置。一次最多读取三个显式目录，摘录有长度限制。

### 项目说明（每工作区一份）

一个工作区只维护一份 `DSH-WORKSPACE.md`，写在**主文件夹**。它按项目分节，汇总主文件夹与全部附加文件夹的内容；附加文件夹不单独生成说明。界面上的「已收录／缺失」依据汇总里有没有对应的项目小节；读不到汇总时显示「无法确认」。

保存文件夹、新增或移除附加目录、切换主目录后会自动重新生成并覆盖该文件；切换主目录时旧主目录里的残留文件会被删除。重新生成只替换插件自己的托管区块，文件里手写的其他内容保留。

说明文档始终落在主文件夹，因为当前会话只允许写主文件夹。


## 开发

```sh
DSH_TEST_PYTHON=python3 npm test
npm pack
```

Windows 上可将 `DSH_TEST_PYTHON` 指向 Python 可执行文件。`npm pack` 生成首发安装包；回归测试不替代真实 GUI 和 WSL 会话验收。
